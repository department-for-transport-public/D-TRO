# Digital Traffic Regulation Orders (D-TRO)

## Release Notes - Version 1.6.0

**Release Date:** 11 September 2026  
**Prepared by:** Ben Pauley

Version 1.6.0 of the D-TRO service was released to the production environment on 11 September 2026. This release introduces a number of new capabilities and service improvements.

## Changelog

- Support for publishing and consuming bridge height restriction data
- Spatial search capability for D-TRO records
- Improved searchability of speed limit orders
- General service performance improvements and defect fixes

## Bridge Height Data

This release introduces support for the creation, maintenance, and retrieval of bridge height restriction records.

A new set of API endpoints has been developed to enable publishers to create, update, and delete bridge height records. Consumers can retrieve individual records, retrieve all available records, or perform spatial searches to identify bridge height records within a specified geographic area.

These endpoints follow the same conventions as the existing D-TRO API and should therefore be familiar to current users of the service.

Further information, including API documentation and example requests, is available via the D-TRO ServiceNow portal.

## Spatial Search Capability

The search endpoint now supports a new request body parameter, `geometry`, which enables consumers to search for D-TRO records located within a specified geographic area.

This capability allows consumers to answer location-based questions, such as identifying all D-TRO records within a county, local authority area, postcode boundary, or other defined geographical region.

Further information on the search endpoint and supported query formats can be found on the D-TRO ServiceNow portal.

## Speed Limit Search

D-TRO records representing speed limit orders can now be explicitly queried through the search endpoint by specifying an `orderReportingPoint` value of:

- `speedLimitValueBased`
- `speedLimitProfileBased`

Although these values are not formally defined as valid `orderReportingPoint` values in the current version of the D-TRO data model, they are expected to become valid in version `5.0.0`.

To support this functionality ahead of the data model release, the service transparently translates these values into the appropriate query criteria and returns matching speed limit records. This provides consumers with a simple and consistent method of searching for speed limit orders without requiring changes to existing integrations once version `5.0.0` of the data model is released.
