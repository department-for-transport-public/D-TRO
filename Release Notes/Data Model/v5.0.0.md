# Digital Traffic Regulation Orders

## Data Model Release Notes - `v5.0.0`

**Release Dates**

![INT](https://img.shields.io/badge/Integration-2nd%20November%202026-red?style=flat-square)

![PROD](https://img.shields.io/badge/Production-30th%20November%202026%20(TBC)-blue?style=flat-square)

`v5.0.0` of the D-TRO Data Model was released to the production environment on 30<sup>th</sup> November 2026. This release includes the following changes to the data model.

## Changelog

- Refactored representation of speed limit restrictions; `speedLimitValueBased` and `speedLimitProfileBased` are now explicit regulation types
- Moved the `regulationType` property from `generalRegulation` to `regulation`, and removed the now-redundant `generalRegulation` property. `regulationType` is now a required field for all orders
- added `other` to `regulationType` enum
- Added `eScooter` vehicle type
- Restricted geometry type usage for speed limit restrictions; `pointGeometry` can no longer be used when representing speed limit orders
- Added `geometryType` field to geometry objects. This takes one of either `full` or `waypoint`, and is designed to represent the fidelity of the submitted geometry
- Enforced the use of `directedLinear` geometry for regulation types that require a direction be given to fully represent the intent. This includes regulation types that represent directional movement permissions, directional movement prohibitions, and highway regulations dependent upon the direction of travel
- Moved mixed order reporting point validation from schema to application validation. See https://github.com/department-for-transport-public/D-TRO/issues/186 for more information
- Fixed a schema validation issue with `permitSubjectToFee` caused by an incorrectly structured object definition. See https://github.com/department-for-transport-public/D-TRO/issues/184 for more information
- added `lastWeekOfMonth` to `calendarWeekInMonthType` enum
- added `lastInstance` to 'instanceOfDayInMonth' enum
- added `lastWeek` to `weekInMonthType` enum
- added `ttroTtmoByNoticeExtension` to `orderReportingPoint` enum
- expanded `conditionalOrderReportingPoints`, which enforce the inclusion of `assignment`, `busRoute`, `bywayType`, `concession` and `tramcar` fields at the provision level, to include the following:
    - `ttroTtmoByNotice`
    - `ttroTtmoExtension`
    - `ttroTtmoNoticeAfterMaking`
    - `ttroTtmoNoticeOfIntention`
    - `ttroTtmoRevocation`
    - `ttroTtmoByNoticeExtension`
    - `variationByNotice`
- added the required `geometryType` field to the `diversionType` object
- removed legacy `residentWithNonResidentBlueBadge` and `residentExcludesNonResidentBlueBadge` values from `permitType` enum
- fixed incorrectly modelled types of `weekinMonth`, `applicableWeek` and `applicableInstanceOfDayWithinMonth` to be arrays
- fixed conditional validation of `madeDate` and `comingIntoForceDate` so that either property is prohibited where the relevant condition is not met, rather than only prohibiting the combination of both. See https://github.com/department-for-transport-public/D-TRO/issues/187 for more information
- tightened validation of `speedLimitProfileBased`; the `type` field is now required and additional properties are no longer permitted
- added validation to enforce the presence of `diverstionType` object and its children for regulated places with a regulated place type of `diversionRoute`, and the absence of this object when suplying other regulated place types
